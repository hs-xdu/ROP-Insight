# ROP-Insight V1.0 技术方案

## 1. 目标与范围

依据 [MVP 设计文档](MVP.md) 和 [第二版设计文档](DESIGN_V2.md)，在已实现的单图查看软件基础上，分 P2、P3、P4 集成分割、分期、量化分析及结果导出，目标为 V1.0 临床可解释辅助诊断原型系统。

当前实现以 Python 3.12 + PyQt6 6.10.2 的 MVP 为基础，包含单图导入、显示、缩放、移动、元信息及异常处理；历史验证见 [MVP 验证记录](VALIDATION.md)。P2-A 后台任务基础已实现，实际操作待按 [P2-A 验收记录](P2_A_VALIDATION.md) 确认；P2 真实模型及后续能力仍待实施。患者管理、数据库、批处理和云端服务不列入本轮范围。

## 2. 技术选型

| 用途 | 方案 | 说明 |
| --- | --- | --- |
| 运行环境 | Python 3.12，Windows 64 位 | 使用项目独立虚拟环境 |
| 桌面界面 | PyQt6 / Qt Widgets | 采用常规桌面窗口与控件 |
| 图像读取 | QImageReader、QImage | 读取 JPEG、PNG 并获取图像信息 |
| 图像显示 | QGraphicsView、QGraphicsScene、QGraphicsPixmapItem | 实现等比例显示、视图缩放和拖动 |
| 应用测试 | pytest、pytest-qt | 覆盖加载逻辑、状态变化与界面交互 |
| 交付方式 | 优先源码运行，后续按需使用 PyInstaller | 打包后在无开发环境的 Windows 机器验证 |

Pillow、OpenCV 保留为按需依赖；当前查看功能优先使用 Qt 自带能力。新增算法选型见第 7—10 节，以复用原实验为优先，不能仅因同名算法可用就替换论文实现。

使用 `venv + pip` 管理环境。开始实现时确定兼容的 PyQt6 版本并锁定依赖；开发依赖与运行依赖分别维护。

## 3. 模块划分

现有结构继续保留，在其基础上增量扩展，暂不引入复杂的插件框架：

```text
src/rop_insight/
    __main__.py             # 启动入口
    ui/main_window.py       # 窗口、操作入口、信息和状态展示
    ui/image_view.py        # 图像显示、缩放、拖动和适应窗口
    services/image_loader.py # 文件校验、解码与读取异常
    models/image_document.py # 当前图像数据和文件元信息
tests/                      # 文档测试与后续应用测试
docs/                       # 需求与技术方案
```

主窗口协调加载服务和图像视图，通过 Qt 信号与槽响应用户操作。加载服务不直接操作界面；图像视图不负责文件选择。图像数据与视图变换分别保存，显示缩放不修改原始像素。

## 4. 核心实现思路

### 4.1 导入与状态

使用文件选择对话框导入单张 JPG、JPEG、PNG 文件，扩展名检查不区分大小写，并用实际解码结果校验格式。文件名、分辨率和格式在成功解码后统一更新；分辨率取自图像数据，格式以读取器识别结果为准。

维护“未加载、加载中、已加载、加载失败”状态。重新导入成功后替换当前图像并重置视图；取消选择不改变当前图像；清除操作同时清空图像、文件信息和视图状态。加载失败时提示原因，保留此前成功加载的图像和信息，并明确提示本次加载失败。

对损坏文件、伪装扩展名、不支持的格式、无权限及文件不存在等情况提供可理解的错误提示。对异常大的图像设置可配置的像素或内存限制，避免无界分配。首版可采用同步读取；若目标样本测试出现明显卡顿，再将读取与解码移到工作线程，QPixmap 创建和界面更新仍在主线程完成。

### 4.2 显示与交互

使用单窗口布局：顶部提供基础操作，左侧展示导入入口和文件信息，中间放置图像视图，底部显示运行状态。

- 图像首次加载后等比例适应窗口并居中，保持原始宽高比。
- 提供滚轮缩放、放大和缩小按钮，设置缩放上下限。
- 通过鼠标拖动平移图像，主要用于放大后查看局部。
- 提供“适应窗口”操作，恢复完整图像显示。
- 适应模式下随窗口尺寸变化重新适配；用户主动缩放后保留当前观察比例，直到再次选择适应窗口。
- 未加载图像时禁用缩放、移动和清除等无效操作。

可使用 `fitInView` 配合保持宽高比实现自适应，使用 `ScrollHandDrag` 实现拖动；实现时关注窗口调整与滚动条变化引起的重复布局问题。相关行为参见 [Qt QGraphicsView 文档](https://doc.qt.io/qt-6/qgraphicsview.html)。

## 5. 测试与验收

应用实现时使用生成的合成图片作为自动化测试样本，避免依赖真实患者图像。加载测试覆盖正常格式、中文路径、扩展名大小写、损坏文件、格式伪装、文件不存在及超限图像；界面测试覆盖重新导入、取消、清除和失败后的状态一致性。

| MVP 验收项 | 验证方式 |
| --- | --- |
| 1 | 在 Windows / Python 3.12 环境启动软件，检查主窗口与初始状态 |
| 2 | 分别导入 JPG、JPEG、PNG 合成图片，断言成功加载和显示 |
| 3 | 使用横图和竖图调整窗口，检查图像完整可见且比例正确 |
| 4 | 验证缩放变换、拖动位置变化及适应窗口后的恢复，并人工检查交互手感 |
| 5 | 将文件名、分辨率和格式与测试图片的已知信息比较 |
| 6 | 导入异常文件，检查提示、旧图保留和状态一致性，确认应用不崩溃 |
| 7 | 人工检查界面布局，并通过代码评审确认模块职责与依赖方向 |

每次改动同步编写或更新相关测试，全部测试和验证通过后创建对应 Git commit。现有文档测试与 pytest、pytest-qt 应用测试作为 MVP 回归基线；新增模块增加独立实验结果对照测试。无界面测试不能代替 Windows 上的实际交互检查。

## 6. 实施顺序与后续扩展

分段任务、前置条件与验收门槛见 [分阶段实施路线图](IMPLEMENTATION_ROADMAP.md)。P2、P3、P4 的版本目标保持不变，每次只实施路线图中的一个子阶段。

1. P2 / V0.2：先审查模型资料与环境，提交详细计划并经人工审核，再实现任务调度、Ridge/Vessel 适配、分期和结果展示。
2. P3 / V0.3：在分割输出验证后集成既有量化代码、连续评分与 RBF-SVM。
3. P4 / V1.0：整合结果、JSON/PNG 导出、追溯信息与系统验收材料。
4. 各阶段通过独立验收后再进入下一阶段；源码运行优先，打包在算法依赖稳定后评估。

算法模块接收原始图像数据并返回独立结果，由界面负责展示。复用 `ImageLoader` 和 `ImageDocument`；将主窗口中新增的分析调度移到独立服务。扩展 `ImageView` 时保留原图项和共享视图变换，切换掩膜或叠加图层不能重新调用会清空场景的 `set_image`，也不能改变原始分析数据。

## 7. 新增功能的技术评估

| 新增能力 | 推荐方案 | 适用性与边界 |
| --- | --- | --- |
| Ridge 分割 | 原实验模型代码和权重的适配器；若为 PyTorch 则沿用 PyTorch | 不重新训练，不自行改架构、阈值或后处理 |
| Vessel 分割 | 锁定原实验采用的 VascX 版本、权重和官方推理入口 | 核对模型仓库、推理包、配置和集成方式，不能将新发布版本当作原实验版本 |
| ROP 四分类 | 复用第四章最终模型及 RGB/Ridge/Vessel 输入管线 | 输入通道、标签顺序、归一化和概率处理必须来自实验配置 |
| 病理结构量化 | NumPy + 原算法代码，按原实现引入 OpenCV、SciPy、scikit-image | 适合数组、形态学、连通域和骨架处理；不自行重写论文特征公式 |
| 严重程度评分 | 第五章评分函数及其拟合参数 | 输出连续值，不能直接解释为临床分期 |
| 结构辅助分类 | 若原模型为 scikit-learn，则复用其预处理 Pipeline 与 RBF-SVM 工件 | 不重新拟合、不调整特征顺序、不默认与深度模型融合 |
| 后台任务 | QObject worker + QThread，首版单任务串行调度 | Qt 信号回传状态和结果；避免多个模型争抢显存 |
| 图层和概率展示 | QGraphicsScene 图层、Qt 控件与表格 | 四类概率使用进度条或条形控件即可，无需额外图表框架 |
| 结构化结果与导出 | dataclass 结果对象、标准库 JSON、Qt PNG 渲染 | 适合本地单图流程，暂不需要数据库或 Web 服务 |

推荐 PyTorch 原生推理作为首选适配路径，前提是原工件确为该框架；若采用 `state_dict`，需同时提供模型定义。模型使用 `eval()`，推理作用域使用 `torch.inference_mode()`；兼容性问题先对照原脚本处理。两者用途不同，不能相互替代，参见 [PyTorch 官方说明](https://docs.pytorch.org/docs/stable/generated/torch.autograd.grad_mode.inference_mode.html)。ONNX Runtime 仅作为后续部署备选，转换必须重新通过一致性测试，P2 不主动增加转换链路。

VascX 官方模型仓库提供权重和模型信息，但仅凭项目名称不足以确定本论文使用的工件。接入前应核对具体版本及其推理代码来源，参见 [VascX 官方模型仓库](https://github.com/Eyened/retinalysis-vascx-models)。

## 8. P2 推理、数据接口与任务调度

### 8.1 图像与结果契约

在保留现有 Qt 图像模型的基础上，新增独立的分析结果对象与数组转换边界：

- 图像：定义 RGB、H×W×3、uint8 的内部交换表示，转换时处理 QImage 行对齐并持有独立内存；这不替代各模型自己的输入预处理。
- 分割结果：分别保留模型原生结果、坐标变换记录及用于原图展示的 Mask。内部二值交换格式建议 H×W、uint8、0/1；对原实验要求 0/255 或其他编码的算法，由适配器显式转换并测试。
- 几何：记录裁剪、缩放、padding、视野范围及逆映射；离散 Mask 使用最近邻插值。概率图的插值和阈值顺序遵循原实验，不将展示时的放大图送入算法。
- 分类：保存类别名称与索引映射、原始模型输出和四类概率，固定 Normal、Stage 1、Stage 2、Stage 3 的展示映射；先确认输出是 logits 还是概率，避免重复 softmax。
- 统一结果：包含 schema_version、image_id、run_id、各模块状态、模型及配置版本、数据来源、错误信息和耗时；大数组保存为独立工件引用。

建议新增 `models/analysis_result.py`、`services/analysis_controller.py`、`inference/`、`quantification/`、`services/result_exporter.py`。具体文件拆分在各阶段 Spec 中确定，不提前生成空模块。

### 8.2 后台执行与一致性

采用 worker-object 模式，把模型加载和执行放在工作线程，界面更新和 QPixmap 创建留在 GUI 主线程。QObject 与 QThread 的线程归属、queued signals 参见 [Qt QThread 文档](https://doc.qt.io/qt-6/qthread.html)。

首版按实际依赖关系串行执行：Ridge 与 Vessel 各自返回结果，分类仅在其必需输入就绪后执行；不依赖失败模块的任务继续运行，依赖缺失者标记 skipped，保留其余成功结果。模型按需加载并评估缓存内存占用，不默认同时常驻 GPU。

每次分析使用 image_id 和 run_id。重新导入、清除或开始新任务后，旧任务的回传结果必须被丢弃。取消采用阶段边界的协作检查，不承诺立即中断正在运行的 GPU 调用；关闭窗口时等待线程安全退出，不强制 terminate。若原库在 Windows 下有依赖冲突，或 Python 密集量化导致线程方案仍卡顿，再评估独立算法进程及其结果协议。

各模块独立维护 pending、running、success、failed、skipped、cancelled 状态，不能继续复用单一图像 LoadState 表达所有分析状态。异常区分模型缺失、加载失败、预处理失败、设备资源不足、无效输出和计算异常，提供操作提示并保留完整本地错误记录。

### 8.3 图层和交互

在现有原图项上增加 Ridge 与 Vessel 的独立叠加项，使用一致的原图坐标、不同颜色和可调透明度；支持原图、单独 Mask、叠加显示。切换结果保留缩放和平移。分期概率与数值表放入可折叠侧栏或标签页，避免挤占小窗口的图像区域。

## 9. P3 量化与辅助分类

量化模块封装原函数而非重新定义指标，逐一记录输入 Mask、视野或 ROI、像素尺度、归一化、参数和输出单位：

- Ridge：面积比例、实心度、外环密度、最大径向位置。
- Vessel：VD、FD、最大局部密度变化、T3、B3；另保留 S_median 接口。
- 严重程度评分：使用第五章原公式、参数和基准，单独展示连续评分。
- 辅助分类：按训练时顺序传入五项常规血管特征、四项 Ridge 特征及 S_median，共 10 项；复用 scaler、缺失值处理器与 RBF-SVM，禁止在单张待测图上 fit。

空 Mask、无骨架、分母为零和特征缺失要沿用原实验规则并返回可用性及原因；不能无条件补零。若资料未明确，先标记 unavailable 并暂停依赖它的辅助分类，不自行假定计算规则。SVM 未训练概率校准时仅输出其已支持的预测，不将 decision_function 当作概率，也不补做训练。

若原模型以 joblib/pickle 保存，仅加载明确来源的实验工件，并锁定原 scikit-learn 与依赖环境；不假定跨版本兼容。保存和版本约束参见 [scikit-learn 模型持久化文档](https://scikit-learn.org/stable/model_persistence.html)。深度分期、SVM 结果和连续评分分别展示，不能默认融合。

## 10. P4 导出与追溯

采用一个分析目录保存 `result.json`、独立 Mask PNG 和分析可视化 PNG。JSON 包含输入文件内容哈希、尺寸、模型权重哈希及版本、预处理和后处理参数、软件 Git 版本、时间、设备、模块状态、指标与工件相对路径。推理工件从 P2 开始记录，P4 完成统一用户导出入口。

使用原始结果生成 JSON，四舍五入仅用于界面；不可用值用 null 配合原因表达，不输出 NaN/Infinity。PNG 在原图坐标渲染，不使用受当前窗口缩放和拖动影响的屏幕截图代替。输出明确标注为模型辅助分析结果，不能标记为医生确认的诊断。

先在临时目录写入并核验全部文件，成功后发布完整结果目录；写入失败不留下看似完整的结果，也不覆盖已有分析。患者原图和本地完整路径不自动复制入导出目录。模型配置采用 JSON，集中管理工件路径、设备、输入尺寸、阈值及版本；大型权重和病例资料使用独立本地目录，不加入普通 Git 提交。
