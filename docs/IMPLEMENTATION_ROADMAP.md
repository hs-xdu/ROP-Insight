# ROP-Insight 分阶段实施路线图

## 1. 实施原则与当前起点

本路线图细化 [第二版设计文档](DESIGN_V2.md) 和 [技术方案](TECHNICAL_PLAN.md)，包含 P2—P4 九个基础子阶段，以及新增 P5—P7 三个增量阶段。现有 P4-B 工程成果是新增阶段的起点，完整 V1.0 验收仍有自动 Ridge 等限制，见 [系统验收](P4_B_VALIDATION.md)。状态以阶段总览及独立验收记录为准，不将测试替身输出当作真实模型结果。

每次实施一个子阶段：先确认 Spec 与实施计划，再开发、审查、运行测试、记录验收结果并提交 Git commit。自动化测试或必要的人工验收未完成时，记录缺口，不标记阶段已完成；通过后再进入依赖它的阶段。本文仅做阶段划分，不启动代码实现。

P2-A、P2-B 使用合成数据搭建公共能力，不依赖模型权重。原实验资料可同步整理；真实算法接入前必须完成工件及环境核对。模型的输入、预处理、输出阈值和数值容差不能由平台实现自行假定。

## 3. P2 平台基础与模型集成

### P2-A 结果契约与后台任务基础

任务范围、文件改动和验收用例见 [P2-A Spec 与实施计划](P2_A_SPEC.md)，用户已按 [验收记录](P2_A_VALIDATION.md) 确认完成。

- **目标：** 让现有查看器具备可测试的异步分析能力。
- **范围：** 定义 image_id、run_id、模块状态、错误和结果对象；制定图像与 Mask 交换契约；增加配置读取、模型适配接口及 QObject worker + QThread 调度。记录本次运行配置与版本。
- **前置资料：** 现有代码和技术方案即可；模型专用参数暂留未配置状态，不填写虚构阈值。
- **交付与验收：** 用可注入的测试适配器验证成功、失败、依赖跳过、取消、重复请求、切图后的迟到结果丢弃和安全退出；MVP 回归通过，并实际检查 GUI 不被分析任务阻塞。
- **边界：** 不加载真实权重，不添加生产环境的随机预测或示例诊断；未配置的模块明确不可用。

### P2-B 图层与结果面板

实现范围与操作步骤见 [P2-B 实施说明](P2_B_SPEC.md)，当前待用户确认实际操作。

- **目标：** 建立稳定的结果展示能力。
- **范围：** 增加 Ridge/Vessel 独立图层、原图/Mask/叠加切换、透明度控制、模块状态及四分类结果面板；保留缩放和平移。
- **前置资料：** P2-A 契约和合成 Mask，尚不需要模型权重。
- **交付与验收：** 使用已知几何图形检查原图坐标对齐、尺寸校验、图层切换、清图与换图；原始数据不随显示改变，窗口缩放和小窗口布局正常。概率面板只展示有合法来源的结果，测试数据限于测试环境。
- **边界：** 只验收展示与接口，不宣称分割或分期已完成。

### P2-C Ridge 模型接入

- **目标：** 完成第一条真实推理链路。
- **范围：** 适配原 Ridge 定义、权重、预处理和后处理，接通后台任务及 Mask 展示，记录权重哈希、版本、参数和坐标映射。
- **前置资料：** 模型定义、权重、推理脚本、原环境、固定参考图与输出，以及预先约定的比较规则；资料清单见技术方案第 12 节。
- **交付与验收：** 对照原脚本验证原生输出与原图映射；测试缺模型、加载失败、解码或推理异常、无效输出及明确支持设备下的运行。生成 Ridge 对照报告。
- **边界：** 不重新训练或改变算法，不用合成结果替代真实输出。

### P2-D Vessel / VascX 模型接入

用户要求暂缓 C、优先 D。已从指定实验目录找到权重、原生推理流程与环境并完成接入，详见 [P2-D 实施与验收](P2_D_SPEC.md)。这不表示 Ridge 已完成，也不替代其后续分类输入要求。

- **目标：** 建立独立的血管分割链路。
- **范围：** 锁定论文实际使用的 VascX 工件与推理入口，适配输出及坐标，接通单独展示和叠加展示。
- **前置资料：** 对应仓库提交、权重、配置、推理环境及参考输出；验证与现有依赖能否共存，必要时先提交独立进程方案供审核。
- **交付与验收：** 与既有脚本对照 Mask、编码和几何映射；验证一个分割模块失败时保留另一模块的成功结果，并正确跳过依赖失败输入的任务。
- **边界：** 不自动升级为与原实验不同的 VascX 版本，不替换第五章的血管量化方法。

### P2-E ROP 四分类与 P2 验收

用户已确认 D 验收，候选见 [模型候选与选择](P2_E_MODEL_SELECTION.md)。随后已明确选择 A6 深圳权重＋导入已有 Ridge，接入与验收见 [A6 实现说明](P2_E_A6.md)。自动 Ridge 仍暂缓，V0.2 总体验收不能以该手动输入模式直接替代完整自动流程。

- **目标：** 达成 V0.2 的真实分割与智能分期流程。
- **范围：** 集成第四章最终分类模型，按实际依赖组织 RGB/Ridge/Vessel 输入；显示 Normal、Stage 1、Stage 2、Stage 3 的预测与概率，保存模型与配置追溯信息。
- **前置资料：** 最终模型及定义、输入管线、标签顺序、概率处理、参考结果和容差；所需上游模块已通过验证。
- **交付与验收：** 对照 logits、概率和预测，测试输入缺失、标签错序及失败恢复；验收三模型联调、旧任务隔离和 GUI 响应。保留 P2 接口说明、测试报告及版本记录。
- **版本门槛：** P2-A 至 P2-E 全部完成真实功能及必要人工验收后，才标记 V0.2 完成。

## 4. P3 量化与辅助分类

### P3-A 病理结构特征

用户要求实施本段，原算法、验证与操作说明见 [P3-A 记录](P3_A.md)。依旧使用手动 Ridge 输入，未宣称自动 Ridge 或整个 V0.3 已完成。

- **目标：** 将已验证的 Mask 转成论文定义的结构指标。
- **范围：** 集成 Ridge 四项特征、血管 VD/FD/最大局部密度变化/T3/B3 及 S_median；记录单位、ROI/FOV、参数和可用性。
- **前置资料：** 第五章原代码、指标定义、区域及尺度规则、归一化参数、退化输入处理规则和参考数值。
- **交付与验收：** 逐指标与原实验对照；覆盖空 Mask、骨架缺失、分母为零及无效区域，并将不可用原因展示出来。
- **边界：** 不凭指标名称重新实现公式，不把缺失值无条件补零。

### P3-B 评分与 RBF-SVM

实现与验收记录见 [P3-B 说明](P3_B.md)。用户已确认按原冻结模型使用 11 项输入（含 T1）。

- **目标：** 达成 V0.3 的量化分析流程。
- **范围：** 集成连续严重程度评分；按训练顺序组合 11 项特征，复用预处理与 RBF-SVM 工件，独立展示评分、辅助分类和深度分期。
- **前置资料：** 原评分函数及拟合参数、特征顺序、SVM/scaler/缺失值处理器、训练环境及基准输出。
- **交付与验收：** 对照特征向量、变换结果、评分及 SVM 预测；确认不重新 fit、不默认融合、不将决策值冒充概率。完成 P3 对照报告及接口说明。
- **版本门槛：** P3-A、P3-B 的真实算法对照和集成验收通过，才标记 V0.3 完成。

- **交付与验收：** 按第二版文档九项总体验收逐项记录证据、问题和结论；确认全流程及部分失败流程可复现，所有必要测试通过，剩余限制明确。

## 6. P5—P7 增量阶段

新增阶段在 P4-B 已有工程能力上实施，不需要恢复已暂缓的自动 Ridge 才能开始，但必须保留手动输入来源与原验收限制。版本号在对应阶段实施时确定，不提前宣布 V1.0 发布。

用户已提供 ropai 本地代码并确认保留当前 ROP-Insight，不迁入旧平台整体。源码盘点、可借鉴字段、算法差异及分步安排见 [ropai 借鉴评估](ROPAI_REUSE_REVIEW.md)。P5先完成报告数据/固定模板，再完成预览/PDF；P6/P7分别借鉴病例关联与历史查询思路，不引入旧Web/MySQL服务。

补充报告目录 deploy_rop_report_web 的简化/详细结构已用于P5设计参考；旧22项经验分档与当前11项/网格不同，不搬用。当前平台已完成固定字段映射、不可用规则、预览和PDF，不依赖旧Web系统。

### P5 结构化辅助分析报告（优先）

用户已授权完成本阶段，使用、接口及验证见 [P5实施记录](P5.md)，范围见 [P5 Spec](P5_SPEC.md)。预览/PDF/精确JSON和关联已实现，P6/P7亦已按后续授权实现，见 [实施记录](P6_P7.md)。

- **前置：** P4-B 的统一分析结果、JSON/PNG 导出与追溯字段；不依赖 P6。
- **范围：** 固定规则与模板生成文字报告，预览及 PDF 导出；包含 A6 类别/概率、Ridge/Vessel 来源及状态、11 项量化特征、连续评分和95%后验区间、SVM 辅助类别、结果限制及模型/软件/模板版本。
- **方案：** 从同一运行快照构造报告数据，供预览和 PDF 共用；使用现有 PyQt6 的富文本与 PDF 输出能力，不引入自由生成临床判断的大语言模型。
- **验收：** 内容与原 JSON/分析值一致，T1 和不可用值不遗漏；A6/SVM 独立、无伪概率；覆盖部分失败、中文/长文本、多页排版、保存失败和同名文件保护。
- **交付：** 报告字段与模板规范、生成服务、预览与PDF入口、内容/版式验证和阶段提交。不新增风险阈值、治疗建议或确诊结论。

### P6 简化病例信息管理（建议）

已实现，字段、界面与验收见 [P6/P7记录](P6_P7.md)。

- **前置：** P5 的报告与运行关联；不改变模型输入协议。
- **范围：** 匿名研究病例编号、左右眼、检查日期和备注，与图像、分析和报告关联；姓名/出生日期等直接身份信息不作为必填字段。
- **方案：** 独立病例元数据及版本，与推理配置和输入分离；先使用本地 JSON/关联文件，避免完整患者数据库及多用户权限系统。
- **验收：** 日期/眼别/备注校验、匿名默认、同病例多图/多次分析、换图不串病例、报告关联一致；资料变更不覆盖旧报告，保存失败不破坏既有关系。患者临床信息不进入分类模型。
- **交付：** 字段与存储规范、基础编辑界面、图像/运行/报告关联、隐私边界及测试。备注仅作展示，不自动产生临床推断。

### P7 历史分析记录与结果复核（可选）

已实现，本地列表、报告重开及来源复核见 [P6/P7记录](P6_P7.md)。

- **前置：** P6 病例关联及 P4/P5 导出；旧 P4 成果无病例/PDF时仍可列出。
- **范围：** 指定本地结果目录的历史列表，按病例编号查看结果、重开报告、查看模型版本和输入文件关联。
- **方案：** 复用导出目录与 JSON，按需建立可重建 JSON 索引，不必立即引入 MySQL 或 SQLite；打开历史结果不重新推理，不修改原结果。
- **验收：** 旧格式兼容、多病例/多眼/多日期、重复编号、目录迁移与索引重建，缺文件/坏JSON/哈希不一致/无权限提示；限制关联文件的目录范围，不遍历整块磁盘或自动复制原图。
- **交付：** 历史列表、结果与报告重开、来源复核界面、格式兼容和异常测试。这里的复核不等同于医生审核或正式诊断签署。
