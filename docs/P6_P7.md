# P6 / P7 实施与验收记录

日期：2026-11-26。范围见 [Spec](P6_P7_SPEC.md)，已完成工程实现及本机自审，待用户人工验收。沿用PyQt6和已有模型，无新增数据库或平台服务。

## 功能与操作

1. 启动 `.\run-platform.ps1`，导入图像，点击左侧“匿名病例信息”。自动匿名编号可以改为既有研究编号，填写眼别、可选检查日期及备注；“保存并关联”时选择本地保存位置。资料保存为新 `rop-case-{revision_id}/case_metadata.json`，包含前版本ID，不覆盖旧版本。取消/写入失败保持原状态；换图重置，避免病例串图。
2. 分析结束后预览或导出报告、导出分析结果。每份新成果附带独立 `case_metadata.json`，绑定图像ID、原文件/解码像素哈希、运行ID和可选报告ID。病例信息默认不强制姓名或出生日期，不进入模型配置或计算。病例编号可重复用于同病例多眼/多次检查；图像、运行、报告和资料版本使用独立ID，列表保留各份记录。
3. “历史分析记录”可在无图像、无模型配置时使用。选择专用成果目录，后台扫描已有P4/P5导出，可取消、刷新重建、按病例编号筛选。表格显示眼别、日期、类型、分析状态、保存/完成时间、运行及校验状态；下方显示病例版本、输入哈希、模型版本/权重哈希与只读原JSON。
4. 选中合格报告可直接重开既有PDF（QtPdf只读窗口）或文字报告，不用新模板重生成。选择原图后后台核对文件SHA256，仅反馈是否匹配，不重关联、不复制原图。关闭窗口会取消扫描/哈希任务并等待安全退出。

## 存储与兼容

- 病例编号1—64字符，仅英文、数字、下划线或连字符且首位字母/数字；眼别未填/左/右；日期合法ISO YYYY-MM-DD，可空；备注最多2000字符。资料版本UUID、带时区时间戳。备注作为用户文本转义展示，不用于推断。
- 分析导出仍为schema_version=1，追加病例文件引用及版本，病例文件进入原工件哈希清单。模型输出字段及推理协议不变。
- 报告仍为report_schema_version=1，模板更新为 `p5-factual-3`，病例放在分析source快照外，source_snapshot_sha256不受资料修改影响。报告JSON、简要/详细文字、HTML、PDF共用同一病例快照，清单记录病例工件及版本。简要备注超过160字符提示查看详细报告；PDF长备注逐行分页。
- 不修改任何旧成果。无病例/PDF的P4记录正常列出“未关联病例”“报告未生成”，无病例的旧P5报告可重开。单独病例资料文件不是分析记录，不单独列入历史。
- 不持久化索引；列表从导出目录在内存重建，整体移动目录后重新选择即可。不同导出包分列，不合并不同运行，也不会把同一次分析和报告误称为一次新推理。

## 完整性与边界

扫描拒绝盘根目录、链接/重解析点、绝对引用、目录穿越和外部URL；仅查所选目录下8层，最多10000目录、5000记录。JSON单文件4MiB、总计64MiB、工件/原图单文件校验256MiB。深于8层的记录不扫描；超量或权限错误提示失败并保留上次列表。后台扫描、原图核对和报告重开前的完整性校验均可取消；文字报告读取上限4MiB。

检查版本、终态、图像/运行关联、manifest身份、分析source哈希、关联工件及病例哈希与版本；缺文件、坏JSON、未知版本、篡改和来源冲突显示问题，不开启异常工件。打开报告前重新校验，检测列表生成后发生的文件变化。哈希不是签名，无法保证未被整套重写的记录真实性。旧P4 result.json没有自身独立签名，不声明其来源经过认证。

病例信息及备注保存在用户选定位置，不自动上传或进入源码；备注由用户填写，可能含身份信息，导出前可预览。当前不能从历史恢复完整可编辑分析会话，历史侧重只读查阅；没有病例删除、数据库、多用户权限、医生签署。自动Ridge继续暂缓，特殊血管指标的新增文字描述继续保留在 [P5后续事项](P5_FOLLOWUP.md)，本轮不实现。
