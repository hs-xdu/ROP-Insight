# P6 / P7 实施约定

用户授权本轮完成P6与P7。保留当前PyQt6、单图流程、固定模板及全部既有模型，不迁移旧Web/MySQL平台，不增加数据库。

P6：匿名研究病例编号、眼别（未填写/左/右）、可选检查日期、备注；默认独立匿名编号，字段单独保存。病例编号限1—64个英文字母、数字、下划线或连字符，首位字母/数字；日期使用合法YYYY-MM-DD，备注最多2000字符。每次保存产生新的revision_id与前一版本ID，绑定image_id及输入哈希；用户选择保存位置，不覆盖旧记录。图像、运行、报告使用各自唯一ID，同病例可多眼/多次分析。病例字段不进入AnalysisController/Worker或模型配置。

P4分析/P5报告导出按需新增case_metadata.json关联文件；P5正文和report.json展示所选病例快照。原result.json的算法数据及source_snapshot_sha256不加入病例字段，分析数值保持不变。换图重置病例，取消或保存失败保留原选择；旧报告不随资料修改而变化。

P7：用户选定本地成果目录，后台扫描现有result.json/report.json及关联文件，显示病例/眼别/日期/运行/模型版本/输入哈希和问题。支持按病例编号筛选、重建列表、查看原JSON/原报告文字、打开经文件及哈希校验的已有PDF、手动选择原图核对文件哈希。旧P4无病例/PDF可正常列出，不生成不存在的报告，不推理、不加载历史权重、不自动复制或全盘搜索原图。

扫描仅在选择目录内，拒绝磁盘根目录、符号链接/重解析点和目录外引用；限制深度、记录数、JSON和文件大小。损坏/未知版本/缺失/篡改/权限问题明确列出；异常记录不能打开未验证工件。校验只表示记录内哈希一致，不表示签名真实性或医生审签。列表按扫描结果在内存重建，不引入持久数据库或不可重建的状态。

测试：字段与绑定校验、版本保存、防覆盖/写入失败、换图/取消/病例编辑不改变分析、报告/PDF同源、旧格式兼容、重复编号多图多眼多日期、目录迁移、重建、缺失/坏JSON/未知版本/越界路径/哈希不一致、后台取消和安全关闭。PDF变更需实际渲染。依序实现P6、P7并完成自审/测试/文档后提交Git；不启动特殊血管指标的后续文字描述。
