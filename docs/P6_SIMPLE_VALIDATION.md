## 打开与操作

```powershell
cd "E:\8 大论文\ROP_System"
.\run-platform.ps1
```

1. 在左侧点击“病例与资料库”，选择新的专用文件夹，例如 `E:\ROP_Insight_Data_Simple`。首次创建两表数据库。
2. 输入匿名病例编号、眼别、检查日期（可清空），点“创建病例”，再点“使用选中病例”。以后可选择同库已有病例。
3. 导入原图和对应Ridge，点“开始分析”，完成后点“保存分析记录”。滚动左侧可见新增按钮。
4. 若需报告，先点“预览辅助分析报告”，再点“保存分析记录”。可在已有无报告记录上补充PDF/文字/JSON；不会覆盖旧报告。
5. 在所选文件夹的records/<运行ID>/中查看original.png或original.jpg、result.json、Mask、叠加图、record_manifest.json，以及可选report子目录。

不选病例可按原流程临时分析；病例窗口的“不关联病例，使用临时分析”可切回。重启后需重新选择资料库文件夹，已存病例仍在。历史查询和工作台恢复留到P7，本阶段不增加历史窗口。

## 简短人工验收

- 创建病例、分析并保存，确认源目录以外确有原图副本和result.json。
- 先不预览报告保存一次，再预览后再次保存，确认同一记录目录中补上report/PDF，没有多一条分析记录。
- 重新分析同一图像后保存，应出现另一个运行ID目录。
- 切换病例后，旧结果保存按钮禁用，提示原所属病例；重新分析后才能保存到新病例。
- 关闭并重启，选同一资料库可找到病例。原图副本不依赖源文件；P7完成后再验收工作台历史恢复。

## 实现与边界

两表：cases（稳定UUID、匿名编号、大小写规范键、眼别、日期、创建时间）；analysis_records（Run UUID作为记录ID、病例FK、原图/结果/可选报告相对路径、分析终态、创建时间、记录及报告清单哈希）。额外字段仅为唯一性/完整性，无第三张表或病例版本。

病例数据库操作、复制、P4/P5导出均通过现有QThread任务执行。分析开始在内存冻结病例与资料库；图像/病例变更后拒绝把旧结果改挂。未选择病例不落库。保存时用ExportSnapshot.capture、snapshot_result、export_bundle、export_report_bundle，原P4/P5字段和模板不变。

原图按原字节复制并检查文件/像素哈希、格式、尺寸。文件先临时写入校验再发布，之后事务登记有效记录。数据库登记失败时没有有效条目；留下已发布目录可在同一请求重试时校验后登记，不实现复杂恢复。报告失败保留已保存分析且report_path为空，允许重试；已有报告不被覆盖。

同一Run重复保存幂等，新Run新目录；记录清单冻结病例信息及分析来源。路径相对资料根，拒绝目录穿越及链接；文件缺失/损坏阻止验证。未添加修改/删除病例或记录、自动备份、多图聚合、归档对比。旧五表catalog.sqlite3目录明确拒绝，不自动迁移或删除旧数据。
