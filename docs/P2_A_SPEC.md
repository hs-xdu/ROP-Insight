# P2-A 任务 Spec 与实施计划

## 1. 状态与目标

状态：用户已批准实施，代码已实现，人工验收待确认；详见 [P2-A 验收记录](P2_A_VALIDATION.md)。依据 [实施路线图](IMPLEMENTATION_ROADMAP.md)、[技术方案](TECHNICAL_PLAN.md) 与 [第二版设计](DESIGN_V2.md)，本任务只搭建可复用的结果契约、配置及后台调度基础，不代表 P2 或 V0.2 已完成。

用户已同意实施本计划；以下为实施范围与验收基准，模型权重不是本阶段前置条件。

实施前的 `MainWindow` 直接协调同步图像加载、`ImageDocument` 和 `ImageView`，已有图像状态与 pytest-qt 回归测试，但没有任务控制器、分析配置和模型接口。本次通过独立服务增加这些能力，保留原有导入与显示行为。

## 2. 范围与数据契约

新增结果类型、JSON 配置加载、可注入适配器协议、单工作线程串行调度，以及主窗口的分析开始/取消入口、状态提示和关闭保护。原图与 Mask 图层、四分类展示留给 P2-B；真实推理、量化、导出留给后续阶段。

| 对象 | 必需字段或约束 |
| --- | --- |
| ImageContext | 每次成功导入生成唯一 image_id；持有独立 QImage 副本、尺寸与来源；取消选择或导入失败保持当前上下文 |
| AnalysisRun | run_id、image_id、schema_version、开始/结束时间、软件版本、配置快照、模块结果；每次运行生成新 run_id |
| ModuleResult | module_id、状态、耗时、输出或结构化错误、模型/配置版本；记录明确的不可用原因 |
| ModuleConfig | enabled、adapter_id、模型版本、权重路径、设备、依赖列表、预处理与后处理参数；模型专用值未配置时不能填默认推理阈值 |
| ModuleError | 模块、错误码、用户提示；完整异常信息写入本地日志，避免在错误提示中暴露整个堆栈 |

接口预先约定 RGB、H×W×3、uint8 的算法交换格式与 Mask 的 H×W、0/1 编码；本阶段传递独立 QImage，不新增 NumPy 依赖或未被使用的数组转换实现。后续真实模型适配时补充数组转换与坐标契约测试。结果输出采用类型明确的载荷，保留原生输出、几何映射和展示结果的扩展位置，不允许任意对象未经验证流入界面。

配置采用带 schema_version 的 JSON，解析后校验字段类型、重复模块、未知适配器、缺失依赖及依赖环；路径相对于配置文件目录解析。未知设备仅作为适配器不支持的配置报错，不自动切换 CPU。未配置的模型默认禁用且给出原因；启动时不导入 PyTorch，不下载权重，不执行动态 Python 路径加载。只从代码注册表选择适配器。

运行中使用不可变或深拷贝的配置及输入快照；不在工作线程读写当前主窗口字段。P2-A 不实现分析记录落盘，但在内存中保存本次配置及版本供后续导出复用；当前软件版本或 Git 信息无法取得时明确记为 unknown，不伪造版本。

## 3. 调度与生命周期

### 3.1 工作线程

使用 QObject worker 移至 QThread。主线程验证请求并按依赖关系生成执行顺序；工作线程执行适配器，回传运行标识、状态和结果。GUI 控件和 QPixmap 始终只在主线程更新。

适配器提供输入校验与执行接口，接收图像快照、所需上游结果、配置及取消令牌。生产注册表此阶段不安装真实适配器；可控成功、失败及延迟适配器仅放在测试目录。缺模型不会触发假预测。

### 3.2 状态和依赖

模块状态为 pending、running、success、failed、skipped、cancelled。正常模块由 pending → running → success/failed；缺少配置、禁用或前置输入失败的模块由 pending → skipped，并记录原因。取消时尚未执行的模块转 cancelled；当前执行模块按取消完成规则收尾。

模块失败后保留已成功结果，与其无依赖关系的模块继续执行；必需输入未成功的下游跳过。运行结束后依据模块状态报告完成、部分成功、失败或取消，不能仅因线程结束就显示“分析成功”。

### 3.3 取消、切图与关闭

- 同时最多运行一个任务；运行时重复请求立即拒绝，不排队、不默默替换。取消完成且线程退出后才接受下一请求。
- 使用线程安全取消令牌，例如 `threading.Event`，避免依赖被长任务阻塞的 worker 事件循环接收取消槽。适配器及模块间检查令牌，不能强制终止线程。
- 取消请求后，即使当前不可中断调用返回，也不再发布它的新成功输出；已发布的成功模块保留，剩余模块标为 cancelled。配置或模型自身失败与取消分开记录。
- 成功换图或清除图像立即失效旧 image_id/run_id 并请求取消；结果接收端同时检查两项标识，不将旧图结果写入新图。取消选择和加载失败不失效仍在显示的图像。
- 关闭时若线程仍运行，先请求取消并延迟关闭，保持 GUI 事件循环响应；收到线程 finished 后清理 worker/thread 引用并完成关闭。长调用未退出时明确等待，不显示已安全退出，不调用 terminate。

## 4. 最小界面与文件改动

只增加“开始分析”“取消分析”按钮和文本状态。无图或无可用模块时禁用开始按钮，显示“分析模块未配置”；测试通过依赖注入启用可控适配器。P2-A 不添加演示模式和虚假的诊断数字。

| src/rop_insight/models/analysis_result.py | 图像上下文、运行/模块状态、结果及错误类型 |

| src/rop_insight/inference/base.py | 适配器协议与显式注册表 |

仅按实际需要增加包初始化文件；保留原 `ImageDocument` 的对外行为，使用组合生成分析上下文。当前 PyQt6 和 Python 环境保持不变；不安装推理与科学计算依赖。临时配置和日志使用独立本地目录，不混入源码和普通 Git 提交。

## 5. 验收用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | MVP 回归 | 现有导入、异常、缩放、移动、元信息及文档测试通过 |
| A02 | 配置加载 | 有效配置及相对路径解析正确；坏 JSON、类型错误、未知适配器、重复项、缺失依赖和依赖环有明确错误 |
| A03 | 后台执行 | 可控适配器在非 GUI 线程运行，GUI 定时器持续触发；结果只在主线程应用 |
| A04 | 成功与追溯 | 输出关联正确的 image_id/run_id、配置快照、版本和终态，快照不受外部修改影响 |
| A05 | 部分失败 | 已成功结果保留，无关模块继续，下游缺输入者 skipped；异常不会逃逸造成进程退出 |
| A06 | 重复请求 | 活跃任务期间重复开始被拒绝，线程未退出前不能开启第二任务 |
| A07 | 协作取消 | 阶段边界生效，取消后不再发布新成功结果，已完成输出保留，线程最终正常退出 |
| A08 | 换图与清图 | 旧任务状态和输出不能污染当前图；取消选择或导入失败保持当前图上下文 |
| A09 | 安全关闭 | 无任务立即关闭；有任务先取消并延迟关闭，GUI 保持响应，退出无运行中 QThread 被销毁 |
| A10 | 未配置界面与实际操作 | 正常运行不出现测试预测；无模型提示明确；Windows 实际操作验证分析时界面响应、取消与关闭 |

自动化采用 pytest/pytest-qt、信号等待和可控线程同步点，避免靠固定 sleep 偶然通过；测试失败需修复后重跑。实际桌面验收无法完成时记录未验证项，不能仅用模拟执行标记本阶段完成。

## 6. 实施步骤与审核范围

1. 定义并测试配置、结果、标识及适配器契约。
2. 实现 worker/controller，测试执行顺序、部分失败、取消、重复请求和结果过滤。
3. 接入主窗口的最小操作与生命周期，补齐换图、清图、关闭和 GUI 响应测试。
4. 运行全量测试，审查 Git diff，完成 Windows 交互验收，更新文档并提交实现 commit。

以上为 P2-A 编码计划的审核范围。通过后只实施 P2-A，不进入 P2-B，不接入真实模型，不宣称 V0.2 完成。若实际库行为要求调整线程或结果契约，先记录并评审变化，再修改计划。
