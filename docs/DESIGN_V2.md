# ROP-Insight 系统后续开发设计文档

**项目名称：** ROP-Insight  
**项目定位：** ROP 临床可解释辅助诊断原型系统  
**开发方式：** Python + PyQt6 + AI 协同开发  
**开发基础：** 已完成的 MVP 软件  
**目标版本：** V1.0 基础目标；P5—P7 为其后的增量规划，版本号待实施时确定

---

## 1. 项目目标

在现有 MVP 软件基础上，逐步集成 ROP 病理结构分割、智能分期、结构量化分析及辅助诊断结果生成功能。

系统最终实现从眼底图像导入到结构化辅助诊断结果输出的完整流程，用于硕士论文研究成果展示与典型病例分析。

### 1.1 开发原则

1. **增量开发**：保留现有 MVP 功能，避免不必要的重构。
2. **模块化设计**：分类、分割、量化及结果展示模块相互独立。
3. **复用研究成果**：沿用论文中已经训练和验证的模型及量化方法，不重新设计或训练算法。
4. **分阶段验收**：每个开发阶段独立完成代码审查、测试和版本提交。
5. **结果可追溯**：保留模型版本、处理参数和结果生成记录。

### 1.2 开发范围

基础范围包含五个功能模块；新增范围见第12—14节。P5报告已完成工程实现和自审，见 [P5记录](P5.md)；P6简化病例信息与P7历史复核仍为规划。

| 模块 | 功能 |
|---|---|
| 图像管理 | 图像导入、预览、缩放与信息显示 |
| 病理结构分割 | Ridge、Vessel Mask 生成与展示 |
| ROP 智能分期 | 四分类预测及概率展示 |
| 病理结构量化 | 病灶、血管指标及异常严重程度量化 |
| 辅助诊断结果 | 结构化结果整合、可视化与导出 |

## 2. 系统总体架构

### 2.1 分层架构

系统采用五层模块化架构。

| 层级 | 职责 |
|---|---|
| 用户界面层 | 图像操作、功能控制、结果可视化 |
| 业务调度层 | 组织分析任务、管理运行状态及异常 |
| 模型推理层 | Ridge、Vessel 分割与 ROP 智能分期 |
| 量化分析层 | 提取结构特征、计算严重程度评分 |
| 数据管理层 | 管理模型配置、输入图像和分析结果 |

各模块通过明确的数据接口交互，不直接依赖界面组件。

### 2.2 主要处理流程

1. 用户导入眼底图像。
2. 系统检查图像有效性并执行必要预处理。
3. 调用 Ridge 和 Vessel 分割模型生成结构 Mask。
4. 调用 ROP 分期模型，生成类别预测及概率。
5. 利用结构 Mask 提取病灶与血管量化指标。
6. 调用第五章已完成的异常严重程度量化与辅助分类方法。
7. 整合分析结果并展示。
8. 保存结构化分析结果及可视化图像。

具体执行依赖关系以各模型实际输入要求为准。若某个模块失败，应保留其他已成功模块的结果，并明确显示失败状态。

## 4. P2：病理结构分割与智能分期

### 4.1 开发目标

将论文第四章涉及的病理结构先验与 ROP 分期模型集成到现有软件中，实现单张眼底图像的结构提取和智能分期。

### 4.2 Ridge 分割模块

**功能要求：**

- 加载已训练的 Ridge 分割模型。
- 接收用户导入的眼底图像。
- 执行与原实验一致的图像预处理。
- 生成 Ridge 二值 Mask。
- 支持原图、Mask 和叠加图像展示。
- 输出供后续量化模块使用的结构数据。

**验收要求：**

- 模型能够正常加载和推理。
- 输出 Mask 的尺寸和编码符合接口约定。
- Mask 与原始图像正确对应。
- 推理异常时能够提示具体原因。

### 4.3 Vessel 分割模块

**功能要求：**

- 加载 VascX 公开预训练模型。
- 执行血管分割。
- 生成 Vessel Mask。
- 支持血管结构可视化。
- 为后续血管量化模块提供输入。

**验收要求：**

- 正常完成分割推理。
- 输出 Mask 满足既有量化算法要求。
- 确保图像尺寸及坐标映射一致。
- 分割结果能够单独展示。

### 4.4 ROP 智能分期模块

**功能要求：**

- 加载第四章最终确定的 ROP 分类模型。
- 按照模型实际要求组织 RGB、Ridge 和 Vessel 输入。
- 输出 Normal、Stage 1、Stage 2、Stage 3 四分类结果。
- 显示预测类别与各类别概率。
- 保存模型版本及推理结果。

**验收要求：**

- 模型能够正确加载和推理。
- 预处理流程与原实验保持一致。
- 软件推理输出与独立实验脚本结果一致（允许预先规定的数值误差）。
- 分类结果不因界面展示或数据转换发生改变。

### 4.5 P2 界面调整

在 MVP 的图像展示界面基础上增加：

- Ridge、Vessel 分割结果切换。
- 分割结果与原图叠加显示。
- ROP 分期结果显示区域。
- 四分类概率显示区域。
- 模型推理状态与异常提示。

### 4.6 P2 交付物

- Ridge 分割模块。
- Vessel 分割模块。
- ROP 分期模块。
- 推理结果展示界面。
- 模型配置及接口说明。
- P2 测试报告与 Git 版本记录。

## 5. P3：病理结构量化分析

### 5.1 开发目标

集成论文第五章已实现的病理结构量化方法，实现从结构 Mask 到量化指标及血管异常严重程度评分的计算。

### 5.2 病灶量化分析

主要提取第五章已经确定的 Ridge 结构特征，包括：

- Ridge 面积比例。
- Ridge 实心度。
- Ridge 外环密度。
- Ridge 最大径向位置。

其他经第五章确认的病灶特征可通过扩展接口添加。

### 5.3 血管量化分析

集成第五章的血管指标计算方法，包括：

- 血管密度 VD。
- 分形维数 FD。
- 最大局部密度变化。
- 血管迂曲度 T3。
- 血管分支指标 B3。
- 血管异常严重程度评分。

另外保留第五章使用的 S_median 指标计算接口。

所有特征的定义、计算区域、归一化参数和处理方法应与原实验一致。

### 5.4 结构特征辅助分类

集成第五章最终确定的 RBF-SVM 分类模型。

按已确认的原冻结模型，使用 11 项结构特征作为输入：

- 常规血管特征 6 项（含 T1）。
- Ridge 结构特征 4 项。
- S_median 1 项。

模型预测结果与第四章的深度学习分类结果独立展示，不默认进行融合。

缺失特征应遵循原模型训练时的缺失值处理规则，不能擅自替换为零。

### 5.5 P3 结果展示

新增量化分析区域，展示：

- 指标名称及数值。
- 指标单位或无量纲属性。
- 血管异常严重程度评分。
- 结构特征辅助分类结果。
- 计算失败或不可用的指标状态。

### 5.6 P3 交付物

- 病灶量化模块。
- 血管量化模块。
- 严重程度评分模块。
- RBF-SVM 推理模块。
- 量化分析界面。
- 与原实验计算结果的对照测试报告。

## 6. P4：辅助诊断结果整合

### 6.1 开发目标

将系统各分析模块的输出整合为结构化辅助诊断结果，形成完整的软件应用流程。

### 6.2 结果组织

最终结果包含四类信息。

| 类型 | 内容 |
|---|---|
| 图像信息 | 图像编号、尺寸及格式 |
| 智能分期 | 预测类别、各类别概率 |
| 病理结构 | Ridge/Vessel 分割结果 |
| 量化分析 | 结构指标、异常评分及辅助分类结果 |

各模型结果保持独立，同时在同一界面集中展示。

### 6.3 可视化展示

- 原始眼底图像。
- Ridge Mask 及叠加图。
- Vessel Mask 及叠加图。
- ROP 智能分期预测。
- 病理结构量化指标。
- 血管异常严重程度评分。
- 结构特征辅助分类结果。

### 6.4 结果导出

支持保存：

- JSON 格式的结构化分析结果。
- PNG 格式的分析可视化图像。
- 输入图像与模型版本的关联记录。

导出结果不得将模型预测标记为经医生确认的临床诊断。

### 6.5 P4 交付物

- 结果整合模块。
- 完整分析界面。
- 分析结果导出功能。
- 系统集成测试报告。
- ROP-Insight V1.0 版本。

## 7. 关键技术与接口规范

### 7.1 模块接口

统一采用以下逻辑接口：

| 模块 | 输入 | 输出 |
|---|---|---|
| 图像加载 | 图像路径 | 图像数据、基本信息 |
| Ridge 分割 | 图像数据 | Ridge Mask |
| Vessel 分割 | 图像数据 | Vessel Mask |
| 智能分期 | 模型要求的图像及结构输入 | 类别、概率 |
| 结构量化 | 图像、Mask、分析参数 | 量化指标 |
| 严重程度量化 | 指定的血管特征 | 连续评分 |
| 辅助分类 | 指定的 11 项结构特征 | 分类结果 |
| 结果管理 | 各模块输出 | 统一结果对象 |

实际接口实现时，需明确图像尺寸、数据类型、Mask 编码、坐标映射和错误返回格式。

### 7.2 模型管理

所有模型统一管理：

- 权重文件路径。
- 模型版本。
- 推理设备。
- 输入尺寸及预处理配置。
- 输出后处理参数。

模型配置与业务代码分离，避免在界面代码中硬编码模型参数。

### 7.3 数据一致性

- 不修改已验证模型的算法实现和权重。
- 不使用与原实验不一致的预处理流程。
- 不擅自调整模型输出阈值。
- 不混用训练时定义不同的 Mask。
- 不将严重程度连续评分解释为临床分期。

### 7.4 运行与异常管理

模型推理和量化计算应避免长时间阻塞 GUI 主线程。

系统至少处理以下情况：

- 模型文件缺失或加载失败。
- 图像格式不符合要求。
- 图像预处理失败。
- 推理设备或资源不足。
- 分割输出无效。
- 量化指标无法计算。
- 结果保存失败。

## 8. AI 协同开发规范

本项目采用第六章确定的 AI 协同开发方法。

每个开发任务按照以下流程实施：

1. **Spec 定义**：明确任务范围、约束及验收标准。
2. **AI 制定计划**：分析现有代码，提出实施方案，不立即修改。
3. **人工确认**：审核方案并批准执行。
4. **分步实现**：控制修改范围，逐步完成代码开发。
5. **代码审查**：检查 Git Diff、依赖变化及实现逻辑。
6. **测试验证**：运行自动化测试和必要的人工验收。
7. **文档更新**：同步项目说明、接口及开发记录。
8. **版本提交**：确认验收通过后提交 Git。

### 8.1 反馈机制

- 需求发生变化：返回 Spec 阶段。
- 设计存在问题：重新制定实施计划。
- 代码审查不通过：返回实现阶段修正。
- 测试不通过：修复后重新测试。
- 无法完成验收：记录问题，不标记为已完成。

### 8.2 项目上下文

使用 `AGENTS.md` 管理项目长期规则。

使用独立 Spec 文档管理各阶段需求。

使用 Git 保存代码版本和开发记录。

将 Codex 标准化工作流封装作为后续改进方向，不列为 V1.0 的必要开发任务。

## 12. P5：结构化辅助分析报告（优先）

### 12.1 目标与范围

将现有分析结果通过固定规则与模板自动组织为文字报告，提供报告预览及 PDF 导出。读取同一次分析的结构化快照，不为生成报告重新推理，不让大语言模型自由作出临床判断。

### 12.2 报告内容

- 图像/分析编号、生成时间、运行状态及输入哈希。
- A6 分期模型的预测类别与四类概率，明确为模型辅助结果。
- Ridge/Vessel 结构信息、Mask 来源及可用性；手动 Ridge 必须标注为用户导入。
- 11 项特征：FD、VD、最大局部密度变化、T1、T3、B3、Ridge 面积比例/实心度/外环血管密度/最大径向位置、S_median；保留单位、网格与不可用原因。
- 连续严重程度评分及 95% 后验区间；不映射为临床分期。
- SVM 辅助分类，与 A6 分别列出；无概率校准时不展示百分比，不默认融合二者。
- 模型/软件/模板版本、分析关联，以及自动 Ridge 暂缓、部分失败、缺失值等结果限制说明。

### 12.3 规则与验收

固定模板只能按现有字段和状态描述已产生的事实，不增加风险阈值、治疗建议或医生确诊结论。失败/取消及缺失指标必须明确说明，不能省略后使报告看似完整或将缺失写成正常。预览与 PDF 来自同一报告数据，数值与 JSON 一致，格式化不改原始精度。

验证正常/部分成功/失败报告，11 项字段覆盖与 T1 展示，长文本、中文、分页、字体和数值读回；PDF 写入失败不覆盖已有报告。交付模板与报告接口、预览/PDF 功能、对照测试及验收记录。P5 不依赖病例管理，未建立病例资料时仍可使用图像/运行编号生成报告。

## 13. P6/P7 精简版（替代此前增量规划）

病例编号采用匿名研究编号，不强制录入姓名；患者临床信息不进入分类模型。左右眼、检查日期按当前精简病例字段保存，不增加备注版本管理。P6包括病例创建/选择与主动保存单图分析及可选报告，SQLite仅cases、analysis_records两表。P7包括病例编号搜索、历史图像与结果恢复及已有报告查看；不推理、不多图聚合、不比较/归档/批量删除。具体需求及阶段以 [精简设计](P6_P7_SIMPLIFIED.md) 为准。
