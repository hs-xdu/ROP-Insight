# P6-B 图像托管实施约定

本阶段已获用户授权。范围：已有Case下的Image登记、原字节托管、可选输入Ridge准备、文件/像素哈希、幂等、保存/完整性状态、取消及异常检测；不实施P6-C运行自动保存、P6-D报告登记或P6-E正式UI。

沿用P6-A五表，不改schema。Image保存眼别/检查日期；病例默认值仅用于调用者预填，服务要求明确传入。图像发布后不可原地换病例、换原图或改变检查事实；修改应新建图像记录。同图多Run在C复用既有图像，不因文件哈希相同自动合并病例。

路径：images/<image_id>/original.png或original.jpg、image_manifest.json、可选inputs/ridge-source.png及ridge-binary.png。原始Ridge保持字节，规范二值副本仅复用原有load_ridge的0/1语义输出0/255 PNG，区分输入与输出。manifest含原图/两个Ridge文件哈希、大小、规范Mask像素哈希和request摘要，不写源目录路径。

由于P6-A工件约束要求input_ridge关联实际Run，B不伪造Run或修改约束：数据库登记original_image和image_manifest两个图像级工件；准备Ridge由受哈希保护的图像manifest列出。C开始真实Run时再建立Run级input_ridge工件。B导入时可选Ridge，已发布图像包保持不可变，后续运行选择不同Ridge属于C。

写入流程：仓库单写入租约 → 保存冻结request.json与pending行 → saving → 同盘临时payload复制及校验 → 原子发布图像目录 → 短事务同时登记两个工件和ready/valid。复制和解码不持有数据库写事务。相同image_id/operation_id及同一请求摘要重试幂等；ID冲突或不同参数明确报错。源文件被移动后，同一冻结请求可直接验证已托管文件，不要求源文件仍存在。

发布后提交失败保留目录及非ready状态；同一请求重试只校验并完成登记，不复制/覆盖已有文件。复制失败/取消清理本次已分配payload文件，保留失败行及request用于检测和重试。无法记录失败时也不得提升ready。遗留writer锁、缺少请求证据、未知暂存目录或发布目录冲突只报待核对，不自动修复；恢复增强仍在F。

只访问安全相对路径，拒绝越界、链接/重解析点，单文件限256MiB，原图沿用40MP解码限制，JSON限4MiB。校验文件哈希、图像尺寸/格式/像素、Ridge二值/尺寸/规范像素、图像清单与数据库关联；异常记录不返回可用图像。数据库ready不是永久有效承诺，发现缺失/损坏要标记并阻止打开。新检查成功才可标valid，不改变保存的分析结果。

后台入口复用ExportController封装单个托管/打开/检查任务，可取消并等待安全退出。独立合成数据验收窗口验证“托管→移走源文件→从仓库重开→损坏检测”，不接模型、不冒充真实预测。正式平台保持原用法。

测试：原图PNG/JPEG/中文名、可选Ridge、源变更/移动、Case修改隔离、哈希/像素/尺寸不一致、请求冲突与幂等、取消/并发/锁/权限/DB提交失败、发布后重试、缺失/篡改/危险路径/链接、后台关闭及全量回归。测试通过后记录结果并创建阶段commit，随后停止等待C授权。
