# P4-A 结果整合与导出

## 使用与内容

使用 `run-platform.ps1` 启动，导入原图及对应 Ridge 后运行分析。任务结束后点击左侧“导出分析结果”，选择已有文件夹。每次在其中建立独立的 `rop-时间-随机ID` 成果目录，不覆盖既有目录。完整成功、部分成功、失败或取消的终态均可导出；失败/取消没有成功输出时只保存状态 JSON。

目录内容：

- `result.json`：schema_version=1、输入图像哈希、任务/软件身份、模块配置/状态/耗时、量化/评分/分类及工件关联。
- `ridge_mask.png`、`vessel_mask.png`：仅生成成功模块提供的图层；保持解码原图尺寸，8 位灰度、0/255 编码。
- `analysis_overlay.png`：存在成功 Mask 时生成；固定原图坐标、Ridge 粉色 `#fb7185`、Vessel 青色 `#22d3ee`、透明度 0.5，后绘制 Vessel。记录这些展示参数。它独立于当前窗口的缩放、拖动、模式、图层勾选及透明度。

不复制原始文件、不保存原始文件名或本地完整路径、不自动带入原实验中间文件。叠加图仍包含眼底影像，导出目录选择框已明确提示。导出内容为研究模型输出，JSON 明确 `research_prototype_not_confirmed_diagnosis`，不表示医生确认的诊断。

## 追溯协议

`image.file_sha256` 是导入时对同一文件句柄读取的文件哈希；`rgb_pixel_sha256` 是解码原图转换 RGB888 后逐行去除 padding 的像素哈希，尺寸单独记录。重新读盘不是导出的前提，源文件删除或改动不会替换已有快照；程序构造的无文件哈希输入明确为 null，不伪造来源。

`run` 保存 image_id 对应关系、run_id、开始/结束时间（UTC）、软件包版本、Git commit 和 dirty 标志。包版本尚沿用 0.1.0 的历史元数据，具体代码以 commit/dirty 为准；非 Git 源码副本无法取得 commit 时为 null，不虚构正式发布版本。

模块记录 adapter、依赖、开关、模型版本、设备、权重哈希、源码哈希和显式前后处理配置；已验证的实际后端参数、原生变换、FOV/bounds、固定后验、特征顺序、原始/变换向量等保留在 `values`。A6 概率与 SVM 独立存放；不可用指标为 null 并有原因。源码哈希中的绝对路径键替换为确定性的 source_ID，保留哈希值，可结合本机配置核对；不导出权重或解释器路径。未知后端字段采用白名单控制，新增字段需审查后纳入。

每个 Mask 的模块条目关联其文件名，`artifacts` 保存 PNG 的尺寸、坐标、编码和 SHA-256。原生后端 Mask 的哈希可能与导出的 0/255 PNG 不同，分别记录，不混用。result.json 自身不保存循环自引用哈希。

## 原子发布与线程

从已结束任务捕获图像/结果/配置快照，GUI 外的 QObject/QThread 完成写入。用户之后换图或清除不改变已选快照。导出时禁止重复请求，窗口关闭等待写入安全结束，不强制终止线程。

在所选父目录建立本次独占的 `.rop-export-*` 暂存目录，完成 PNG、JSON 写入和读回验证，JSON flush/fsync 后以同一文件系统目录重命名发布。失败只清理本次暂存目录；存在目标目录时拒绝覆盖。进程被操作系统强制杀死或断电可能遗留暂存目录，发布的成果目录不会是半套文件；这不是断电持久性保证。报错后允许重试。
